\# CareFlow — Clinical Pathway Process Mining: Data Module



\## 1. Purpose



This data module feeds the \*\*CareFlow\*\* process-mining pipeline — Project 3 of the

Infotact Solutions Advanced Data Analytics (Vol. II) brief.



The goal is to simulate realistic \*\*Electronic Health Record (EHR)\*\* event logs from

a hospital Emergency Room so that process-mining algorithms (PM4Py) can discover

the "As-Is" clinical pathway, expose hidden bottlenecks, and support conformance

checking.



\---



\## 2. Column Reference



| Column | Type | Description |

|--------|------|-------------|

| `case\_id` | string | Unique patient visit ID (e.g., `C0001`). One case = one ER visit. |

| `patient\_id` | string | Anonymized patient identifier (e.g., `P10234`). |

| `activity` | string | Clinical activity. One of: `Triage`, `X-Ray`, `Blood\_Test`, `Doctor\_Consult`, `Admit\_Ward`, `Discharge`. |

| `timestamp` | datetime | Event time in `YYYY-MM-DD HH:MM:SS`. Monotonically increasing per case. |

| `resource` | string | Staff member who performed the activity (e.g., `Nurse\_Jane`, `Dr\_Smith`). |

| `department` | string | Hospital department: `Emergency`, `Radiology`, `Pathology`, `Ward\_3`. |

| `age` | integer | Patient age in years (18–85). |

| `gender` | string | `M` or `F`. |

| `insurance\_type` | string | `Private`, `Medicare`, `Medicaid`, or `Self-Pay`. |

| `loop\_back\_flag` | string | `Y` / `N`. Marks a return to a previously visited activity (the planted bottleneck). |



\---



\## 3. How the Data Is Generated



\### 3.1 `sample\_event\_log.csv` — Hand-Made Journeys (Day 2)

\- \*\*10 patients\*\* (`C0001`–`C0010`), written by hand.

\- Covers every variant path the pipeline must handle, including double loop-backs.



\### 3.2 `event\_log.csv` — Generated with Fixed Seed (Day 10)

\- \*\*500 patients\*\*, \~2,250 events.

\- Generated by `scripts/generate\_event\_log.py` with `random.seed(42)`.

\- Deterministic: the exact same file is produced on every machine.



\### 3.3 `quality\_report.csv` — Validation Counts (Day 9)

\- Output of `scripts/validate\_event\_log.py`.

\- One row per check: `check\_name`, `expected`, `actual`, `status` (`PASS`/`FAIL`).

\## 4. ⚠️ Synthetic Only — No Real Patient Data



> \*\*This dataset is 100% synthetic.\*\*

> - No real patients, staff, hospitals, or insurance records.

> - All names (`Nurse\_Jane`, `Dr\_Smith`, etc.) are fictional.

> - `patient\_id` values are sequential and contain no PHI.

> - This dataset must never be presented as real clinical data.



\---



\## 5. 🌱 Planted Ground Truth (The Hidden Bottleneck)



As specified in the CareFlow project brief:



> \*"40% of patients are being sent back to Triage after an X-Ray due to a specific

> missing paperwork form."\*



This is \*\*deliberately planted\*\* in the generator:



| Planted Rule | Value |

|--------------|-------|

| Loop-back rate after X-Ray | 40% |

| Loop-back always returns to | `Triage` (`loop\_back\_flag = Y`) |

| Second loop-back (deeper) | \~15% of loopers |

| Admission rate | 40% |

| Blood test inclusion | 45% |

| X-Ray inclusion | 55% |



\*\*Expected measurable outcome after mining:\*\*

\- PM4Py discovers a graph where \*\*Triage ⇄ X-Ray\*\* is the dominant edge.

\- Conformance checking flags \~40% of X-Ray cases as non-compliant.

\- Removing the loop reduces ER wait time by \~20 minutes.
