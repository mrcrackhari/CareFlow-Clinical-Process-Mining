# CareFlow — Clinical Pathway Process Mining: Data Module

**Owner:** Member 1 · **Branch:** `member1-data`
**Project:** CareFlow (Infotact Solutions, Advanced Data Analytics Vol. II)
**Data:** 100% synthetic — no real patient data anywhere in this repo.

---

## 1. Purpose

This data module feeds the **CareFlow** process-mining pipeline. It simulates
realistic **Electronic Health Record (EHR)** event logs from a hospital
Emergency Room so that process-mining algorithms (PM4Py) can discover the
"As-Is" clinical pathway, expose hidden bottlenecks, and support conformance
checking.

---

## 2. Column Reference (frozen contract — per TEAM_STRUCTURE §5)

| Column | Type | Description |
|--------|------|-------------|
| `case_id` | string | Unique patient visit ID (e.g., `CASE-0001`). One case = one ER visit. |
| `activity` | string | Clinical activity. One of: `Registration`, `Triage`, `Doctor Consultation`, `X-Ray`, `Doctor Review`, `Discharge`. |
| `timestamp` | datetime | Event time in `YYYY-MM-DD HH:MM:SS`, 24h, no timezone. Monotonically increasing per case. |
| `resource` | string | Fictional staff member (e.g., `Nurse_Jane`, `Dr_Smith`, `Tech_Miller`). Enables filter-by-doctor drill-down (Day 12). |
| `shift` | string | `Morning` (06:00–13:59), `Evening` (14:00–21:59), `Night` (22:00–05:59). Enables shift filter (Day 12). |

**Rules (per TEAM_STRUCTURE §5):**
- Sort by `case_id`, then `timestamp`.
- Two events in one case must not share a timestamp.

## 4. How the data is generated

### 4.1 `sample_event_log.csv` — hand-made (Day 2)
- 10 patients (`CASE-0001` … `CASE-0010`), 58 events total.
- Covers every variant path including a double loop-back.

### 4.2 `event_log.csv` — generated (Day 3–4, frozen Day 10)
- 500 patients, generated by `src/data/generate_events.py`.
- Deterministic: `random.seed(42)` — the same file is produced on every run.
- Planted bottleneck (see §5 below).

### 4.3 `quality_report.csv` — validation (Day 9)
- Output of `src/data/validate_events.py`.
- One row per check: `check`, `rows_checked`, `rows_failed`.

## 6. 🌱 Planted Ground Truth (The Hidden Bottleneck)

Per the project brief:

> *"40% of patients are being sent back to Triage after an X-Ray due to a
> specific missing paperwork form."*

This is **deliberately planted** in `src/data/generate_events.py`:

| Planted rule | Value |
|--------------|-------|
| Loop-back rate after X-Ray | **40%** |
| Loop-back returns to | `Triage` |
| Deep second loop | ~15% of loopers |
| X-Ray inclusion | 55% of patients |
| Doctor Review inclusion | 45% of patients |
| Discharge vs Admit | 60% discharge |

**The Day-9 test (`tests/test_metrics.py`, owned by M2)** must recover this
40% rate from `event_log.csv` — proof that the pipeline works end-to-end.
